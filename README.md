# 言据

[![CI](https://github.com/yanxulang/yanju/actions/workflows/ci.yml/badge.svg)](https://github.com/yanxulang/yanju/actions/workflows/ci.yml)
[![言序](https://img.shields.io/badge/言序-1.0-c43b2f)](https://github.com/yanxulang/yanxu)
[![许可](https://img.shields.io/badge/许可-MIT-2f855a)](LICENSE)

言据（YanJu）是言序专用的纯中文数据交换格式，文件后缀为 `.yj`。它保留 JSON 简单、递归、易交换的值模型，同时把结构词和值词换成中文形式。

```yanju
据【
  「项目」：「言据」，
  「后缀」：「.yj」，
  「格式版本」：1，
  「实现语言」：「言序」，
  「稳定」：真，
  「能力」：列【「解析」，「序列化」，「文件读写」】，
  「备注」：空
】
```

解析器和序列化器全部写在 [`src/言据.yx`](src/言据.yx) 中，没有 Rust 实现，也没有借用 `标准:JSON` 解析言据。库只复用言序已有的文字、数学和受权限控制的 UTF-8 文件能力。

## 格式一览

| 数据 | 言据写法 | 言序值 |
| --- | --- | --- |
| 据 | `据【「键」：值】` | `典` |
| 列 | `列【值，值】` | `列` |
| 文字 | `「青青子衿」` | `文` |
| 数值 | `7`、`-3.14` | `数` |
| 逻辑 | `真`、`假` | `理` |
| 空值 | `空` | `空` |

言据只接受全角 `：`、`，` 和 `【】`。据键必须是文字，重复键与尾随逗号会被拒绝。完整定义见[言据格式规范 v1](规范/言据-v1.md)。

## 引入项目

需要言序 1.0 或更高版本。在应用的 `言序.toml` 中声明 Git 依赖：

```toml
[依赖]
言据 = { git = "https://github.com/yanxulang/yanju.git", 修订 = "v1.0.0", 版 = "^1" }
```

然后从包入口导入：

```yanxu
引「包:言据」为 言据；

定 配置：典 为 言据.解析据（「据【「语言」：「言序」，「版本」：1】」）；
言 配置【「语言」】；
言 言据.美化（配置）；
```

在本仓库或未使用包依赖时，也可直接导入 `src/言据.yx`。

## 标准库接口

| 接口 | 作用 |
| --- | --- |
| `解析（文）` | 解析任意言据根值 |
| `解析据（文）` | 解析并要求根值为据 |
| `解析列（文）` | 解析并要求根值为列 |
| `校验（文）` | 返回文字是否为完整合法言据 |
| `序列化（值）` | 生成按键排序的规范单行言据 |
| `美化（值）` | 生成两空格缩进的言据 |
| `读取 / 读取据 / 读取列（路径）` | 读取 UTF-8 `.yj` 文件 |
| `写入 / 美写（路径，值）` | 规范或美化写入 `.yj` 文件 |

精确签名与错误行为见 [API 文档](docs/API.md)。文件接口受调用程序 `言序.toml` 中 `[权限].文件` 的约束。

## 本地验证

```sh
yanxu 查 src/言据.yx
yanxu 试 tests
yanxu 字节 tests/解析与往返.yx
yanxu examples/生成数据.yx
yanxu 字节 examples/生成数据.yx
```

测试同时覆盖树解释器和独立字节码 VM。CI 在 Linux、macOS 与 Windows 上执行同一组检查。
