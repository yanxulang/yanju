# 言据 1.2 使用指南

## 五分钟上手

在格式 2 清单中锁定稳定标签：

```toml
[依赖]
言据 = { git = "https://github.com/yanxulang/yanju.git", 修订 = "v1.2.0", 版 = "^1.2" }
```

解析、验证并生成稳定文本：

```yanxu
引「包:言据」为 言据；

定 配置：典 为 言据.解析据（"据【「端口」：8080，「调试」：假】"）；
定 规则：典 为 {
    「类型」：「据」，
    「必需」：【「端口」】，
    「属性」：{「端口」：{「类型」：「数」，「最小」：1，「最大」：65535}}
}；
言据.断验（配置，规则）；
言 言据.序列化（配置）；
```

## 处理不可信输入

为每种协议设置与业务匹配的上限，不要依赖进程级资源预算：

```yanxu
定 限制：典 为 {
    「最大字符」：65536，
    「最大深度」：24，
    「最大容器项」：4096
}；

定 结果：典 为 言据.尝试解析（正文）；
若 结果【「成功」】则
    定 值 为 言据.解析受限（正文，限制）；
终
```

`尝试解析` 使用默认限制；需要自定义限制且不想抛错时，在调用方捕获 `误` 并通过 `错误详情` 获取稳定代码。

## 配置合并和补丁

```yanxu
定 最终 为 言据.合并据（默认配置，用户配置）；
定 补丁：列 为 言据.差异（默认配置，最终）；
定 重放 为 言据.应用补丁（默认配置，补丁）；
```

补丁项包含 `操作`、路径段列 `路径`、`旧值` 和 `新值`。重放修改或删除前会比较旧值；冲突返回 `YJ_PATCH_CONFLICT`，调用方应重新读取基础值并重新计算差异，不应跳过校验强制覆盖。

## HTTP

发送言据时使用 `言据.版本媒体类型`，正文使用 `序列化`。接收时先以服务端正文上限读取，再验证：

```yanxu
若 非 言据.是言据媒体类型（内容类型）则
    抛 「不支持的内容类型」；
终
定 数据 为 言据.解析受限（正文，{「最大字符」：1048576}）；
```

普通 JSON 只能通过 `自JSON` 显式转换，不能凭正文形状自动识别为言据。

## 数据库

跨数据库保存完整言据文本时：

```yanxu
定 入库文：文 为 言据.数据库文本（值）；
定 出库值 为 言据.自数据库文本（入库文）；
```

需要审计数据是否规范时使用 `是规范文本` 或 `自规范数据库文本`。原生 JSON 存储应先映射为数据库 JSON 值；导出 `.yj` 时仍须调用言据规范序列化。

## 流

言据流 v1 是换行分帧协议。每个非空行恰好一个值，美化后的多行文档不能直接作为一帧：

```yanxu
定 解析器 为 言据.流式解析器（）.限制（{
    「最大字符」：8192，
    「最大深度」：16，
    「最大容器项」：1024
}）；
逐 值 于 解析器.送入（分块）则 处理（值）；终
逐 值 于 解析器.结束（）则 处理（值）；终
```

## 错误处理

程序逻辑只判断 `YJ_*` 代码，不匹配消息文字。常用代码：

| 代码 | 含义 |
| --- | --- |
| `YJ_PARSE` | 语法错误 |
| `YJ_SIZE` / `YJ_DEPTH` / `YJ_ITEMS` | 资源限制 |
| `YJ_SCHEMA` / `YJ_TYPE` | 规则或值类型问题 |
| `YJ_PATH` | 路径不存在或类型错误 |
| `YJ_PATCH` / `YJ_PATCH_CONFLICT` | 补丁无效或旧值冲突 |
| `YJ_CANONICAL` | 文字不是规范形式 |
| `YJ_IO` | 文件操作失败 |

完整签名见 [API.md](API.md)，格式、校验和流的规范见仓库 `规范/`。
